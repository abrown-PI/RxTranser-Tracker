🆕 What's New (August 2026)

Quick rundown of the latest updates so the team isn't surprised by changed behavior.

Partial-receive for bulk shipments (mark what's missing)

  • When you receive a bulk shipment and some prescriptions didn't actually make the box, you no longer have to check every Rx or nothing. Use Receive Partial and check off only what you have — anything unchecked gets flagged as missing so the fill pharmacy knows to look.
  • The fill pharmacy sees the missing items highlighted on the shipment and gets a Teams notification.
  • Transfers where the entire shipment for that patient was missing are automatically pulled off the bulk box, reverted to In Progress, and put back on the fill queue for the next shipment.

× Reship missing (fill pharmacy pulls flagged Rx off a Received bulk)

  • Once the receiving pharmacy flags a prescription as missing (via Receive Partial), the fill pharmacy can open the shipment and click × Reship missing next to that transfer.
  • That transfer comes off the bulk shipment/packing slip and goes back to In Progress so it lands on the next box out.
  • Available only for transfers that were flagged as missing — if the receiver marked the whole shipment as fully received, the button doesn't appear.

× Remove / × Not in box (before a shipment is received)

  • Pending bulk — the origin pharmacy sees a × Remove button on each transfer in the shipment to correct an over-packed manifest before the box goes out.
  • In Transit / Delivered — same button, labeled × Not in box. Use it if you realize a script was added to the packing slip but didn't physically ship. The transfer is pulled off the shipment and reverted to In Progress.

Intake Location field

  • New Transfer / Edit Transfer now has an Intake Location field — where the call or fax was originally received (may be different from the Origin/dispensing pharmacy).
  • Useful for cross-store call routing: the person who took the intake can be traced back even if a different location becomes the origin.

Urgent / High-Priority flag + same-store warning

  • Mark any transfer as 🚨 Urgent on the New/Edit form — it gets a red badge on all lists and sorts to the top so the fill team sees it first.
  • If you accidentally set the Origin and Fill to the same store, a yellow warning appears at submit-time so you can catch the mis-route before saving.

Mark as Duplicate of #___

  • Found two transfers for the same patient/Rx? Open the duplicate → click Mark as duplicate of #___ → type the ID of the canonical transfer. The dupe closes with a link pointing to the original so the history stays clean.

Per-transfer History (audit trail)

  • Every transfer detail modal now has a History section showing every status change, edit, shipment add/remove, question, and comment with a timestamp and the user who did it.
  • Use it when investigating "how did this get to X status?" or "who changed the ship-to address?"

Search by Transfer ID

  • The top search box now matches Transfer IDs (e.g., 21680) in addition to patient names, Rx#s, and drug names. Faster jump to a specific transfer.

Teams routing improvements

  • Questions and status alerts now route to the correct pharmacy chat based on the effective origin — for non-transfer pickup orders, that's the pickup pharmacy, not the fill pharmacy. So if Erie is compounding but Jamestown is doing the pickup, the alert lands in the Jamestown chat.
  • Erie (the hub) is excluded from routing — an Erie-only transfer notifies whoever's on the other side.

Admin: view/edit stored Teams webhook URLs

  • Admins can now audit + edit the raw Teams webhook URLs on the Admin page instead of hunting through Azure Storage Explorer. Fixed a bug where the password-manager autofill duplicated the same URL across every location.

Drug name required on every Rx line

  • The Rx items table now requires a drug name on every populated line. Catches the case where someone tabbed past the datalist without picking a value — no more transfers submitted with a blank drug field.

Refill fix: no more ghost file metadata

  • Fixed a bug where creating a refill sometimes carried over stale file metadata from the source transfer (making it look like a file was attached when it wasn't). Refills now start clean and inherit only real, uploadable files.

Printing no longer changes status

  • Printing a transfer / summary sheet used to auto-advance the status to In Progress. That's gone — print freely without touching status.

July 2026 (previous month)

Active / Complete / All view toggle on Transfers

  • The old Show completed checkbox is gone. In its place: a three-button toggle — Active, Complete, All — right next to the status dropdown.
  • Active (default) hides transfers that are complete for your pharmacy. What "complete" means depends on which side you're on:
    • Fill pharmacy (Erie for compounds) — closes out at Shipped. The package left; your work is done.
    • Receiving pharmacy (destination for pharmacy ship-tos and pickup orders) — closes out at Received. You still see it in Active until someone at your pharmacy checks it in.
    • Patient direct-ships — closes out at Shipped for everyone. No in-pharmacy receive step.
    • Canceled — closes out for everyone immediately.
  • Complete flips the view so you only see transfers that are closed out for your pharmacy.
  • All ignores the completion rule — same behavior as the old "Show completed" checkbox on.
  • Admins in All-locations mode: set the Origin filter to a pharmacy to see that pharmacy's Active view. Without a filter, a transfer is considered complete only when both sides are done (received or canceled).
  • If you had saved a default view with "Show completed" set, the app migrates it automatically the first time you load — no reconfiguration needed.

Anticipated Ship Date now saves reliably

❄ USP Overnight Shipping Policy

Effective June 2026 (from Megan Smith / clinical leadership):

Several of our compounded sterile medications now require overnight cold shipping to comply with updated USP standards. Patients receiving these medications are now charged $50 for overnight shipping directly to their home, rather than the previous 2-day option. Per USP regulations, these sterile-prepared medications must be shipped overnight and stored frozen.

Existing patients (6-month rule): If the patient has filled the medication within the last 6 months they get one complimentary overnight shipping; future fills are $50.
New patients or no fill in 6+ months: charged $50 on this fill.

Medications requiring overnight shipping

  • Tacrolimus ophthalmic
  • Cyclosporine ophthalmic
  • Medroxyprogesterone injection
  • Estradiol ophthalmic
  • Oil-based injections, including:
    • Testosterone
    • Testosterone combination products
    • Estradiol (oil)
    • Progesterone (oil)
    • Other oil-based injectable formulations

How the portal helps

  • When you type one of these drugs on the New Transfer or Edit Transfer form, a yellow warning box pops up under the Items section with the policy reminder and a recommended charge.
  • Once the patient name is filled in, the warning checks the patient's history: it tells you "✨ Complimentary this fill" (if last fill was within 6 months) or "💰 Charge $50" (new patient or 6+ months since last fill).
  • The Delivery Charge dropdown now includes a $50 (USP overnight) option — set this when the patient is being charged.
  • A portal-wide yellow banner reminds the team until they dismiss it.

Admins: editing the warning list

Go to Admin → Drug Warnings. You can:

  • Edit the match patterns — one pattern per line, space-separated terms (all must be present). Example: tacrolimus ophth matches drugs containing both "tacrolimus" and "ophth" (case-insensitive).
  • Change the headline, body, and complimentary / standard messages that appear in the warning box.
  • Change the charge amount ($50 today; if pricing changes, update here).
  • Change the complimentary window (6 months today). Set to blank if the rule doesn't apply.
  • Uncheck "Active" to disable a warning without deleting it.
  • + Add Warning to create new rules for future policies — the same engine works for any drug-policy callout.

Creating a New Transfer

Two ways: Single Transfer (one at a time) or Bulk Upload (many transfers from a multi-page PDF).

Single Transfer

  1. Click + New Transfer
  2. The form opens with Single Transfer mode selected. Fill in:
    • Patient Name (required)
    • Patient info (DOB, allergies)
    • Routing: Origin Location + Fill Location
    • Shipping: Ship-to (Pharmacy or Patient), address. If you pick Pharmacy, the origin pharmacy's address auto-fills.
    • Billing Method
    • Patient Price (optional) — for the team to record the price charged to the patient. Surfaces on the detail modal and on the Summary Sheet printout.
    • For future appointment? (optional) — when checked, set the appointment date. The anticipated ship date auto-calculates backward from the appointment so the box arrives in time.
    • Anticipated Ship Date — auto-calculated from the destination pharmacy's receiving day(s). Editable.
    • PK Transfer Sheet upload (required for normal transfers — drop a PDF, app auto-fills the fields it can read)
    • Optional: Hard Copy Scan, Formula, Transfer Notes
    • Items / Prescriptions: Origin Rx #, Receiving Rx # (filled in by fill location later), Drug, Qty
  3. Click Submit transfer
Non-transfer pickup at another pharmacy? Check the blue box at the very top of the form before entering patient details. See the Non-Transfer Pickup section above.
Temporary patient address? When Ship To = Patient, a "🏖 Temporary address" checkbox appears in the Shipping section. Toggle it on, optionally set a "Through" date — the receiving pharmacy will see a warning banner telling them not to update the patient's permanent address.
Tip: Upload a clean PDF transfer sheet first — the app auto-fills patient, DOB, drug, Rx# from the document. You just verify and submit.

Bulk Upload (recommended for the weekly stack)

Drop a multi-page PDF that contains multiple transfer sheets and the app splits them automatically.

  1. Click + New Transfer → toggle to Bulk Upload top right
  2. Set the bulk-level defaults if all transfers in this file share them:
    • Fill Location — applies to every draft
    • Anticipated Ship Date — applies to every draft
    • 📍 Non-transfer — check this if the whole stack is prepared-for-pickup orders (not real transfers). Set the Pickup pharmacy that appears next to it. Every draft inherits both. You can still override the pickup pharmacy per row from the queue table dropdown, and drafts flagged non-transfer skip the PK sheet requirement.
  3. Click 📁 Select PDFs to upload and pick the file(s)
  4. The app processes each page:
    • For digital PDFs with selectable text: pdf.js extracts fields instantly
    • For scanned/image-only PDFs: Azure AI OCR reads each page (takes ~30-60 seconds for a 22-page file)
  5. Each "PATIENT Rx TRANSFER INFORMATION" page becomes one draft. Pages between transfer headers attach as hard copies to the preceding draft.
  6. Review the queue — drafts marked ⚠ Needs Review are missing required fields
  7. Click Edit on any draft to fix fields. Inside the editor:
    • 📄 View attached pages shows you the actual PDF pages assigned to this draft
    • Save & return to queue saves edits
    • Save & Approve saves AND immediately commits the transfer to the live system
  8. Click Approve on each ready draft, or Approve all N ready at the top to do them in one shot
The queue persists. Close the tab, sign out, leave the browser — when you come back, your in-progress bulk drafts are still there waiting. Use Clear queue to remove everything if you want a fresh start. Page images (for the View Pages button) are kept only during the active session and won't survive a browser reload.

Non-Transfer Pickup at Another Pharmacy

Use this when the order is originating from the filling pharmacy and being shipped to another pharmacy for the patient to pick up there. This is NOT a normal transfer — the receiving pharmacy doesn't put anything in their dispensing system, they just hand off the prepared scripts when the patient walks in.

How to use it

  1. Click + New Transfer
  2. At the top of the form, check the blue box "📍 Prescriptions will be picked up at another pharmacy (Non-transfer)"
  3. Pick the Pickup pharmacy from the dropdown. The Shipping address fields auto-fill with that pharmacy's address.
  4. Continue filling out the rest of the form like a normal transfer (patient, drugs, etc.)
  5. Submit

Both the filling pharmacy AND the pickup pharmacy will see the order on their Transfers list, so the pickup pharmacy knows they have an order coming.

PK Transfer Sheet is optional on non-transfer orders. The order originates at the fill pharmacy, so there's no transfer paperwork to attach. Upload one if you have it; the app won't block you if you don't.

Bulk pickup orders

Some weeks you send a stack of prepared scripts to another pharmacy as a single batch (e.g., 12 scripts for the Seminole pickup window). Instead of entering each patient:

  1. Check the 📦 Bulk pickup order box inside the pickup section
  2. Enter Number of scripts and a short Description (e.g., "Weekly batch of compounds for Seminole pickup customers")
  3. The Patient and Items sections are no longer required for bulk pickup orders
When NOT to use bulk pickup: If the receiving pharmacy will fill the script themselves (i.e., a true transfer), enter each one as a normal transfer with individual transfer sheets. Bulk pickup is only for the prepared-and-shipped-for-pickup case.

Refilling an Existing Transfer

Receiving pharmacies — use this, not + New Transfer. If the receiving pharmacy is processing a refill for an order that's already been transferred once, always use the Refill flow (+ Refill tab or the 📋 Refill this Rx button on the transfer detail). This keeps the refill chained to the original so the full Rx History stays connected. Entering it as a brand-new transfer breaks that connection.

From an in-app transfer (normal path)

  1. Click + Refill (top tab)
  2. Search by patient name, Origin Rx#, or Receiving Rx#
  3. Click Refill this → on the right transfer
  4. Review the Shipping & Payment Defaults (auto-pulled from the original). Click Edit if anything changed (new address, different billing).
  5. Check the Prescriptions boxes for which Rx to include in this refill (some patients have multiple Rx and may only need one refilled)
  6. Click Continue to refill form →
  7. The form opens pre-filled. PK transfer sheet, hard copies, formula, and Rx numbers all carry over from the original — same prescription, same paperwork. Review everything, replace any document if something changed, then click Submit.
Refills don't require a hard copy scan (optional) and inherit the original's docs, so you usually don't have to upload anything new.

From the transfer detail (one-click)

Open any transfer → click 📋 Refill this Rx at the top → fills out the new transfer for you. Same carry-over behavior.

Refill of a transfer NOT in the app (legacy / manual)

For patients whose original transfer pre-dates the app, you can enter a refill manually:

  1. Click + Refill → scroll past the search results
  2. Click + Enter Refill Manually in the dashed box at the bottom
  3. The form opens marked as Refill / Manual / Legacy with a gray "Prior Transfer Info" section at the top
  4. Fill in whatever you have for the original: prior pharmacy, prior Rx #, prior transfer date, notes (all optional)
  5. Fill out the rest like a new transfer (patient, drugs, PK sheet upload, etc.), then submit

The Prior Transfer Info section will appear on the transfer detail so the receiving pharmacy can see the context. This option is temporary — once enough refill history is in the app, you'll always find the original via search.

Viewing the refill chain

Open any transfer that's part of a refill chain — the detail modal shows an Rx History section listing the original at the top plus every refill below in chronological order. Each row shows the date, item count, and status. Click Open on any row to switch the modal to that entry. Works whether you opened the original or any refill.

Editing or Deleting a Transfer

Edit (all roles)

  1. From the Transfers tab, click any row to open the detail modal
  2. Click ✏️ Edit Transfer at the top
  3. Change anything: patient info, routing, ship-to, billing, documents, transfer notes
  4. Click Save changes

Use this to fix typos, update the ship-to address, swap the wrong origin pharmacy, or add documents that came in later.

Delete (admin only)

On the detail modal, admins see a 🗑 Delete button at the bottom-left. Click it and confirm — the transfer is removed permanently. Cannot be undone.

Quick inline edits

  • Receiving Rx # — fill location staff can type the Rx# directly on each item row in the detail modal (no need to open Edit Transfer)
  • Status from the All Transfers table — each row has a status dropdown right in the table. Change it without opening the row. Choosing "Canceled" still routes the transfer to Action Items for acknowledgment.
  • Status from the detail modal — Update Status dropdown at the top of the modal
  • Tracking + dates — click Edit ship / tracking on the detail modal. Entering a tracking number auto-flips status to Shipped.

Asking a Question About a Transfer

Use this when you need info from another pharmacy.

  1. From the Transfers list, find the patient → click ❓ Ask question on that row.
    (Or open the transfer and click ❓ Ask Question at the top.)
  2. Type your question, click Send Question
  3. The other location's Teams gets a notification with a button to open the transfer (admin must have set up the webhook for that location)
  4. They reply in the transfer's Discussion section
  5. Your reply appears for them on their Alerts tab

You can see questions YOU asked that are still unanswered on the Alerts tab → "Questions You've Asked" section.

The Alerts Tab

The Alerts tab shows three sections:

  1. Open Questions — questions other team members asked YOUR location, waiting for your answer. Click Answer → to open the transfer.
  2. Questions You've Asked — your own pending questions still waiting on a reply.
  3. Transfers Past Status Time Limit — transfers stuck in one status too long (admin-configurable). Click any row to open and update.

The number badge on the Alerts tab = open questions for you + overdue transfers combined.

Credit Card Workflow

The CC Authorization form options only appear on the New Transfer / Edit Transfer form when you set Billing Method = Credit Card and the card is NOT already on file. The form has the PI logo, patient + Rx pre-filled, and a written authorization clause — no signature line.

Two ways to capture the card info:

Option A: Print blank, fill by hand, scan back in

  1. On the transfer form, set Billing Method to Credit Card
  2. Click 🖨 Print blank form
  3. A one-page PDF prints with patient name and Rx auto-filled
  4. Customer / cardholder writes in their card info on the paper
  5. Scan the completed form
  6. Upload the scanned file in the same section, then submit the transfer

Option B: Fill on screen, save as PDF, upload

  1. Click ✏️ Fill on screen instead of Print blank
  2. A new window opens with the same form, but the card fields are editable inputs
  3. Cardholder types in their info (name, billing zip, card #, expiration, CVV)
  4. Click 🖨 Save as PDF / Print at the top — pick "Save as PDF" as the destination
  5. Upload the saved PDF in the same section, then submit the transfer
Card data stays local. Whether you scan the paper or save as PDF, the card number is only entered on the customer's side. The app never transmits typed card data to the backend — same PCI posture as the original paper-scan flow.

Billing team opens the transfer → clicks the print-the-signed-form button (visible on the detail modal when a CC form is attached) when they need to charge.

Shipments

WorldShip Customer Reference — the bridge between this app and FedEx

This is the most important thing to understand about shipping: every time you generate a FedEx label in WorldShip, type either the Transfer ID or the BULK Shipment ID into WorldShip's "Customer Reference" field. The daily auto-match cron looks up FedEx shipments by reference and links the tracking back to the transfer or bulk shipment in this app — automatically. No manual tracking number entry.

  • Patient-direct ship — Customer Reference = the Transfer ID (visible at the top of the transfer detail modal in a yellow band)
  • Bulk pharmacy-to-pharmacy ship — Customer Reference = the BULK Shipment ID (e.g., BULK-2026-0042, shown after you create the shipment in the app)

Creating a Bulk Pharmacy Shipment (weekly box to another pharmacy)

  1. Shipments tab → + Create Shipment
  2. Destination Type: Pharmacy, To: pick the destination pharmacy
  3. The list below auto-loads transfers in In Progress heading to that pharmacy. (New / Pending Clarification / Needs Formula transfers don't appear here — they have to be moved to In Progress first.) Check the ones in this box.
  4. Tip: filter the list by Anticipated ship on or before to focus on what's due today.
  5. Carrier: FedEx. Tracking number is optional here — leave it blank.
  6. Click Create Shipment
  7. The app shows the new BULK Shipment ID prominently. Write it down or memorize it.
  8. The app offers to print a packing slip with the PI logo, BULK ID, Code128 barcode, From/To addresses, and the manifest. Put it inside the box.
  9. Go to WorldShip and generate the FedEx label. Type the BULK ID into WorldShip's Customer Reference field.
  10. Done. The daily auto-match cron will find the FedEx shipment by reference, link the tracking number to this bulk, and cascade it to every transfer in the box. Status auto-advances to Shipped.
You can come back later to add tracking manually if needed — open the bulk shipment in the Shipments tab and use Edit ship / tracking. But for typical FedEx shipping, the cron handles it.

Creating a Ship-to-Patient transfer

Patient-direct ships don't need a bulk shipment record. When you generate the FedEx label in WorldShip, type the Transfer ID (shown at the top of the transfer detail modal) into the Customer Reference field. The auto-match cron picks it up and links tracking to that transfer.

Seeing both directions — Incoming vs Outgoing

Pharmacies see both shipments going TO them (incoming) and shipments going FROM them (outgoing) on the Shipments tab by default. Each row has a colored chip in the first column showing direction relative to your location:

  • Green ← Incoming — shipments to your pharmacy
  • Blue → Outgoing — shipments from your pharmacy

Use the [All] [← Incoming] [→ Outgoing] toggle in the filter bar to scope to one direction.

You can also filter by Ship date range (top of the page) to scope to a particular shipping window.

Next-shipment banner

The blue strip just under the navbar shows "📦 Your next pharmacy shipment to [your location] is expected on [Day MM/DD/YYYY]" — computed from your location's receiving day(s) configured in Admin → Pharmacy Mailing Addresses. If your location receives shipments multiple days a week (e.g., Tue and Thu), the banner shows the nearest upcoming day and lists the full schedule in parens.

Receiving a Shipment

  1. Shipments tab → focus the 📷 Scan tracking barcode field at the top
  2. Scan the FedEx barcode OR the bulk packing slip barcode
  3. The shipment opens — click 📦 Arrived at my pharmacy when the box is in your hand
  4. Check off each Rx as you unpack it
  5. Take photos of any damage with the camera button
  6. Click Mark Package Received

📦 Packing Checklist (shipping team's daily worksheet)

The Packing Checklist replaces paper sheets the shipping team used to assemble manually. Pulls in every transfer scheduled to ship today, groups by destination pharmacy, and lets staff check items off as they pack. Each check is saved to the backend so other users (and managers) see live progress.

Opening the checklist

  1. Go to the Shipments tab.
  2. Click 📋 Packing Checklist (top-right, next to Pull from FedEx).

Payment Status ( Auto-Sync + Paid in Store)

Payment status now updates automatically when a patient pays in Tabz (or Tabz creates a cart). You only need to click anything when the patient pays at the counter — that's the Paid in Store override.

The Payment column

The All Transfers table has a Payment column showing the rolled-up status for the whole transfer (based on every Rx on it):

  • Pending — no payment activity yet from Tabz.
  • 🛒 Tabz Cart Created — Tabz has built a cart for the patient (text/email sent). Waiting on payment.
  • Partial — some Rx are paid, some still pending.
  • ✓ Paid (Tabz) — fully paid through Tabz.
  • ✓ Paid in Store — billing team / counter marked it paid manually (patient paid at the pharmacy).
  • Canceled — Tabz canceled the order.

The Pay Date column shows when the payment posted.

Tabz auto-sync — how it works

  • Tabz sends the portal an event each time a prescription goes pending → cart created → paid → canceled. The portal matches it to a transfer by Rx number first, then by patient name + recent transfer (7-day window) as a fallback.
  • When matched via patient name, the portal also back-fills the Rx number on the item so the next event matches directly without the fallback.
  • Receipt PDFs are pulled and stored automatically when an Rx is marked paid — viewable from the item row in the detail modal.

Per-Rx detail

Open any transfer's detail modal — each Rx row shows its own Tabz status badge so you can see exactly which scripts are paid and which are still in the cart. (Helps when a patient pays for 2 of 3 scripts and you need to know which one is still outstanding.)

The "💲 Paid in Store" override

The Actions column shows a small blue 💲 icon button on any transfer that isn't fully paid yet — including ones with a Tabz cart already created. Click it when the patient walks in and pays at the counter. The Payment column flips to ✓ Paid in Store immediately.

Why the icon shows on Cart Created rows: Sometimes Tabz has built a cart but the patient pays in person before they get to it. The 💲 button lets you override without waiting for Tabz.

From the transfer detail modal

Same 💲 Mark Paid in Store button is in the Shipping & Billing section. Once marked, it shows ✓ Paid in Store by [Name] on [Date] with an Undo button.

FedEx Tracking — Auto, Manual, & Click-through

You typically don't have to do anything here — the app handles tracking automatically as long as the WorldShip Customer Reference is set correctly when you generate the label. There's also a manual fallback for when the auto-match misses, and every tracking number in the app is a clickable link to FedEx's tracker.

How auto-match works

  • A scheduled job runs once a day (12:00 UTC, ~7-8 AM ET)
  • For every open transfer without tracking, the job queries the FedEx Track API by reference using the Transfer ID
  • For every open bulk shipment without tracking, the job queries by the BULK ID
  • Any match found: tracking number + ship date are written to the transfer/bulk. Status flips to Shipped.
  • Bulk matches cascade — when a BULK ID matches, the tracking is applied to every transfer in that bulk
  • Every 15 minutes while you're on the Shipments tab, the app re-polls FedEx for live status updates on every active shipment. Delivered only flips on FedEx's strict "DL" code — "Out for delivery" or "Delivery delayed" do not falsely mark a package delivered.

Manual pull on demand (Shipments tab → Pull from FedEx)

If you don't want to wait for the daily cron, click 📦 Pull from FedEx on the Shipments tab to trigger the same lookup right now. Queries every open transfer + every open BULK shipment. Results show what was matched. Note: FedEx's reference index can lag the actual label by up to a day, so a same-day pull may miss; the daily cron re-tries the next morning automatically.

Manual tracking entry (when auto-match misses or you need it now)

Every bulk shipment modal has a FedEx Tracking row with an ✏️ Edit (or + Add tracking manually) button:

  1. Open the bulk shipment from the Shipments tab.
  2. Click ✏️ Edit on the FedEx Tracking row.
  3. Paste the FedEx tracking number from WorldShip (10–22 digits).
  4. The app validates, saves, and immediately queries FedEx for live status. If FedEx says it's already in transit / delivered, the shipment's status updates and the tracking cascades to all transfers in the bulk.

Clickable tracking links

Every tracking number shown anywhere in the app (Shipments list, Transfers list, transfer detail modal, Action Items, FedEx Pull results) is a clickable link that opens FedEx's public tracker in a new tab. No more copy/paste to FedEx.com.

The key thing: typing the Transfer ID or BULK ID into WorldShip's Customer Reference field is what makes auto-match work. The Packing Checklist's barcode column lets staff scan instead of type. If you forget, you can still paste a tracking # manually via the bulk shipment modal.

Common Questions

Q: I picked the wrong origin pharmacy and submitted. Can I fix it?
A: Yes — open the transfer → ✏️ Edit Transfer → change origin → Save.

Q: I leave the Bulk Upload page mid-review. Will my drafts be there when I come back?
A: Yes. The bulk queue is saved automatically and persists across reloads. Page-image previews disappear after a reload (no harm — you can still edit and approve), but draft data stays.

Q: The bulk upload only detected 4 transfers but my PDF has 11. What do I do?
A: Open browser DevTools (F12) → Console tab. Look for "OCR page N:" log lines. The ones where isTransferSheet=false are the missed ones. Copy a snippet of their firstChars text and send it to whoever maintains the app — they'll tune the detection.

Q: I deleted a transfer by accident. Can I get it back?
A: No. Delete is permanent. Reach out immediately if you need a record reconstructed — depending on backup state, it may or may not be recoverable.

Q: A patient changed their address. How do I update for refills?
A: Edit the existing transfer with the new address before refilling, OR start the refill and use the Edit button on the Shipping & Payment Defaults to override.

Q: We canceled a transfer — does the app know?
A: Change the status to Canceled on the transfer. It will show up under Action Items until someone acknowledges it. This prevents accidentally shipping it.

Q: How do I see all transfers for one patient?
A: Use the search bar at the top of the navbar — type their name. Results include their transfers AND shipments.

Q: Can I export the list?
A: Yes — Reports tab → Export CSV at the bottom.

Q: I forgot my local-account PIN.
A: An admin can reset it from Admin → Users & Access → click Reset PIN on your row.

Q: The original transfer isn't in the app — how do I record a refill?
A: + Refill tab → scroll to the bottom → click + Enter Refill Manually. You can put whatever you know about the original (prior pharmacy, prior Rx #, date) in the gray "Prior Transfer Info" box. The rest of the form works like a new transfer. This is temporary — once enough history is in the app, you'll find originals via search.

Q: My default location keeps showing the wrong pharmacy.
A: Sign out and back in (or refresh the page) — the app reads your assigned location from the admin's Users & Access list on each sign-in. If it's still wrong, the admin needs to update your row.

Q: Do I have to enter a tracking number when I create a bulk shipment?
A: No, leave it blank. Generate the FedEx label in WorldShip with the BULK ID in the Customer Reference field. The daily auto-match cron links the tracking automatically. If you'd rather, you can manually paste a tracking # later via Edit ship / tracking on the bulk shipment.

Q: I forgot to type the Transfer ID / BULK ID in WorldShip — what now?
A: Open the transfer (or bulk shipment) → Edit ship / tracking → paste the FedEx tracking number manually. It'll set the status to Shipped just like the auto-match would have.

Q: I checked off some Packing Checklist items. Will my teammates see my checks?
A: Yes — checks live on the transfer record in the backend, not in your browser. Your teammates' checklists update within ~30 seconds of you clicking. A small green "✓ [your name]" appears under each box so anyone can see who packed which item. Same goes for the reverse — your view will pick up their checks within ~30 seconds.

Q: My Packing Checklist checks disappear at midnight — is that a bug?
A: No, that's intentional. Checks are date-stamped, and the checklist only counts today's stamps. Yesterday's checks are kept in the audit history but don't show as "packed today" anymore — so each morning everyone starts fresh.

Q: An order is ready earlier than its anticipated ship date and I want to pack it today. Do I have to edit the transfer?
A: No — use the 📥 Add Order to Today button on the Packing Checklist. Search by patient or transfer ID, click Set to Today, and it appears on the checklist immediately. The transfer's anticipated ship date is updated (and the origin pharmacy gets the standard Teams notification for the date change).

Q: The app keeps loading me back into the Transfers tab when I refresh — can I land on a different one?
A: Yes, that's been fixed. Whatever tab you were on when you refresh, the app now restores. Click any tab once and it becomes your new default until you click another.

Q: Where do I see all refills for a patient/Rx?
A: Open any transfer in the chain → the Rx History section shows the original and every refill in order. Click Open on any row to switch the modal to that entry.

Q: I don't see my new transfer when trying to add it to a shipment.
A: The shipment list only shows transfers in In Progress status. Open the transfer and bump the status to In Progress, then it'll appear. New, Pending Clarification, and Needs Formula transfers don't appear (they're still being worked).

Q: I'm at the receiving pharmacy and need to process a refill for a transfer that's already in the app. Do I enter it as a new transfer?
A: No — use the Refill flow. Either + Refill tab → search for the patient → Refill this, OR open the existing transfer → 📋 Refill this Rx button at the top. This chains the refill to the original so the full Rx History stays connected. Entering it as + New Transfer breaks that connection and creates an orphan record.

Q: My pharmacy gets shipments twice a week. Can I set that?
A: Yes. Admin → Pharmacy Mailing Addresses → for your location, check all the days you receive shipments (e.g., Tue and Thu). The anticipated ship date auto-calc and the next-shipment banner both use the nearest day from the multi-day schedule.

Q: Why does the next-shipment banner sometimes say "Set your location's receiving day(s)"?
A: Your location doesn't have any receiving days configured. An admin needs to go to Admin → Pharmacy Mailing Addresses and check the day(s) of the week for your location.

Q: My order is held up because we need clarification from the origin pharmacy. What status do I set?
A: Change the transfer's status to Pending Clarification (or Needs Formula if it's specifically a missing formula). Setting either status automatically pings the origin pharmacy's Teams chat so they know to respond. The order stays in this status until you bump it back to In Progress.

Q: The anticipated ship date needs to change because we can't ship on time. What should I do?
A: Open the transfer → ✏️ Edit Transfer → change the Anticipated Ship Date → Save. If you're at the fill location (not the originating pharmacy), the origin pharmacy automatically gets a Teams notification with the old and new dates.

Q: Where does the green Paid badge come from?
A: Either the row's "💲 Mark Paid / Charged" button on All Transfers OR the same button on the transfer detail. Click once — done. The badge shows who marked it and when.

Q: My session signs me out after I leave the screen for a while. Why?
A: For security, the app signs users out automatically after 30 minutes of inactivity. A warning banner shows up at 28 minutes — move the mouse or press a key to reset the timer and stay signed in.

Q: Can I send the same script to multiple pharmacies for pickup?
A: Each non-transfer pickup goes to one pickup pharmacy per record. If a single batch is going to multiple destinations, enter one bulk pickup per destination.
